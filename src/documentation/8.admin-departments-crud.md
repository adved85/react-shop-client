# Admin Departments CRUD
### List, Create, Edit, Show & Delete — Step-by-Step Guide

---

## Overview

This guide documents the first full CRUD section of the admin dashboard: **departments**.
It follows lesson 6 of the course ([video](https://youtu.be/T63BM5XEZjU?list=PLRB0wzP8AS_GMe_1P-hAZOYjn-a2CdhWA)).
The lesson builds a **categories** section; this project built **departments** first with
the same pattern, and categories will follow it.

The steps below are in the order the work was done.

**What was done:**

1. **Departments CRUD in the admin dashboard:** list, create, edit, details and delete,
   connected to the Laravel API (Steps 2, 8–10, 13).
2. **Breadcrumb navigation** in every admin page, replacing the section heading in the
   layout (Step 1).
3. **Reusable components** for tables and states: `SpinnerGrow`, `EmptyState`,
   `TableMessageRow`, `TableSpinnerRow` (Step 3).
4. **Feature folders and `AdminLayout`:** `admin/dashboard/` and `admin/departments/`,
   with `Dashboard.jsx` renamed to `AdminLayout.jsx` (Step 4).
5. **A simpler API layer:** one API file per resource, called directly by components
   (Step 5).
6. **Server validation errors shown on form fields**, through a shared
   `src/utils/form.js` (Step 11).
7. **Backend support:** the departments endpoints and their validation rules (Steps 6, 14).

**Key decisions:**

1. **Each admin page renders only what changes.** The layout lives once in
   `AdminLayout`; pages render into its `<Outlet>` (Steps 1, 4).
2. **Components are declared at the top level of a file, never inside another
   component** (Step 3).
3. **Error handling lives in `client.js`.** Components only write the success path and
   UI cleanup (Step 7).

**The chain for every department page:**

```
Sidebar / Link  →  /admin/departments/...  →  <Outlet> in AdminLayout  →  Department* page  →  src/api/adminDepartments.js
```

## Step 1 — Layout: Breadcrumb Instead of a Heading

In the course design, the layout shows a heading above the sidebar with the name of the
selected section, and each section re-renders the whole dashboard. Here the layout stays
untouched and each page renders only its own content:

- The heading was removed from the layout.
- Each page shows a **breadcrumb** built from the current URL with React Router's
  `useLocation`.

**`src/components/common/Breadcrumb.jsx`**
```jsx
import { Link, useLocation } from "react-router-dom";

const Breadcrumb = () => {
  const { pathname = "" } = useLocation();
  const segments = pathname.split("/").filter(Boolean);

  const segmentToLabel = (segment) => {
    const decoded = decodeURIComponent(segment);
    return decoded.charAt(0).toUpperCase() + decoded.slice(1);
  };

  const items = segments.map((seg, idx) => {
    const isLast = idx === segments.length - 1;
    const href = "/" + segments.slice(0, idx + 1).join("/");

    if (isLast) {
      return <li className="breadcrumb-item active" aria-current="page" key={href}>{segmentToLabel(seg)}</li>
    }

    return (
      <li className="breadcrumb-item" key={href}>
        <Link to={href}>{segmentToLabel(seg)}</Link>
      </li>
    )
  });

  return (
    <nav aria-label="breadcrumb">
      <ol className="breadcrumb m-0">
        {items}
      </ol>
    </nav>
  )
}
```

- `/admin/departments/9/edit` shows **Admin / Departments / 9 / Edit**.
- The last item is plain text with `aria-current="page"`, not a link to the page you are on.
- `key={href}` is unique even if two segments have the same name; `key={seg}` would not be.

> **Tip:** a `map` callback with a block body (`{ ... }`) can use a normal `if` and return
> different JSX per branch, as above. Inside JSX itself, use a ternary instead.

## Step 2 — The List Page: Header + Table

`DepartmentsContent.jsx` has two blocks:

1. **Header:** breadcrumb and a **Create** button, in a `col-md-12` flex row with the
   items spaced apart.
2. **Table:** one row per department, with **edit** and **delete** icons.

The edit icon was converted from the SVG code in `src/assets/images/snippets.txt` into
`src/assets/images/icons/edit.svg`, next to the existing `trash.svg`. Both are imported
as React components through SVGR (`?react`).

Data is loaded once, when the page mounts:

```jsx
const [departments, setDepartments] = useState([]);
const [loading, setLoading] = useState(true);

useEffect(() => {
  getDepartments()
    .then(setDepartments)
    .catch(() => {}) // the interceptor already showed a toast
    .finally(() => setLoading(false));
}, []); // [] runs once, when the component mounts
```

**Why not `const response = await getDepartments()` at the top of the component?**
A component is a plain function that must return JSX synchronously, and it runs again on
every render. Fetching belongs in `useEffect`, and the result goes into state.
`setDepartments` triggers the re-render that shows the data.

## Step 3 — Loading and Empty States as Components

The temporary `<tr><td colSpan={6}>Loading ....</td></tr>` row was replaced by the same
spinner the Login page uses. The spinner became a reusable component, now used on the
Login page and in the tables.

**`src/components/common/SpinnerGrow.jsx`**
```jsx
const SpinnerGrow = () => {
  return (
    <div className="text-center">
      <div className="spinner-grow text-secondary spinner-grow-sm" role="status"></div>
    </div>
  )
}
```

The table's helper parts were extracted from `DepartmentsContent` into their own
components, named for what they do:

| Component | What it is | Location |
|---|---|---|
| `TableMessageRow` | a full-width table row for a message | `common/table/` |
| `TableSpinnerRow` | `TableMessageRow` with the spinner | `common/table/` |
| `EmptyState` | "No departments found." | `common/` |
| `DepartmentRows` | the department rows (`<tr>`s) | `admin/departments/` |

> **Important:** declare components at the top level of a file. A component declared
> inside another component is a **new component type on every render**, so React
> unmounts and remounts that part of the tree, and any state inside it is lost.

**`src/components/common/table/TableMessageRow.jsx`**
```jsx
const TableMessageRow = ({ children, colSpan = 6 }) => {
    return (
        <tr>
            <td colSpan={colSpan}>{children}</td>
        </tr>
    )
};
```

The table body is now one line:

```jsx
<tbody>
  {loading ? (<TableSpinnerRow />) :
    (<DepartmentRows data={departments} onDelete={deleteDepartment} />)
  }
</tbody>
```

## Step 4 — Folder per Feature, and `AdminLayout`

`admin/content/` (one file per sidebar item, from [guide 5](5.admin-dashboard-navigation-and-auth-hardening.md))
was replaced by **one folder per feature**:

```
src/components/admin/
├── AdminLayout.jsx          ← was Dashboard.jsx

│   └── DashboardContent.jsx

    ├── DepartmentEdit.jsx
    └── DepartmentShow.jsx
```

**Why:** each resource gets a list, rows, a create form and an edit form. Grouping by

**`Dashboard.jsx` → `AdminLayout.jsx`:** the file renders `Layout`, `Sidebar` and an
`<Outlet>`, and wraps **every** admin page, not just the dashboard. The dashboard page
itself is now `dashboard/DashboardContent.jsx`. `AdminLayout` is the admin counterpart of
`common/Layout`.

## Step 5 — API Layer: One Endpoint Key, No Pass-Through Services

**1. One endpoint key per resource.** The five department functions share one base path:

**`src/api/endpoints.js`**
```js
adminDepartments: {
    link: "/admin/v1/departments",
}
```

**`src/api/adminDepartments.js`**
```js
const { link } = ENDPOINTS.adminDepartments;

export const getDepartments = (page) => api.get(link, {params: {page} });
export const storeDepartment = (data) => api.post(link, data);
export const updateDepartment = (id, data) => api.put(`${link}/${id}`, data);
export const showDepartment = (id) => api.get(`${link}/${id}`);
export const destroyDepartment = (id) => api.delete(`${link}/${id}`);
```

**2. Names follow the resource.** Files are named after the API resource they call
(`adminDepartments`, `adminAuth`), so the API file, its endpoint key and its consumers
match.

**3. Components import from `src/api/` directly.** The services only awaited the API
function and returned the result, so they were removed. `src/services/example.service.js`
shows the kind of logic that justifies a service: combining requests, reshaping data for
the UI, caching. See [guide 3](3.backend-api-integration.md), Step 7, and
[guide 6](6.testing-and-lint.md), Step 6, for the matching doc and test changes.

## Step 6 — Backend List Endpoint

On the Laravel side, `DepartmentController::index` returns departments sorted by `order`:

```php
$departments = Department::orderBy('order')->get();

return $this->apiResponse->ok(DepartmentResource::collection($departments));
```

- No `in_use` filter, so the admin list shows inactive departments too.
- `->get()` returns a plain array. With only a few departments there is no pagination
  yet; the footer shows **Total**. For later, `ApiResponse::paginated()` returns
  `{ items, pagination, links }`.

## Step 7 — Error Handling Lives in `client.js`

Every API call goes through the interceptors in `src/api/client.js`. For a failed
request they already:

- show a toast for the common error codes (`400, 401, 403, 404, 409, 422, 429`);
- redirect to the login page on `401`;
- retry `GET`s on `500` / `503`;
- **reject with the original axios error**, so the component's `catch` still runs.

So components only write:

```jsx
try {
    setDisabled(true);
    const response = await updateDepartment(id, data);
    // success: toast, navigate
} catch {
    // the interceptor already showed a toast
} finally {
    setDisabled(false);
}
```

1. **`try`** because `await` can throw.
2. **`catch`** so a failure is not an "Uncaught (in promise)" error. Leave it empty with
   a comment, or use the error (Step 11). Write `catch {` without a variable when the
   error is not used; `catch (error)` with an unused `error` is a lint error.
3. **`finally`** to undo UI state (spinner, disabled button) whether the call succeeded
   or not.

> **To do:** read `client.js` end to end. It was written with AI help, and every
> component relies on what it does.

## Step 8 — Create

The **Create** button links to `/admin/departments/create`. Because the list page
already renders under `/admin/departments`, the relative `to="create"` would also work.
Check the route in `App.jsx` and the sidebar link when choosing.

```jsx
<Route path="departments" element={<DepartmentsContent />} />
<Route path="departments/create" element={<DepartmentCreate />} />
<Route path="departments/:id" element={<DepartmentShow />} />
<Route path="departments/:id/edit" element={<DepartmentEdit />} />
```

The form uses `react-hook-form`. On success:

```jsx
const response = await storeDepartment(data);
toast.success(`${response.name} created!`, { autoClose: 1000 });
navigate("/admin/departments");
```

It navigates straight away, so the button can't be clicked a second time while waiting.
The toast stays visible after navigating, because `<ToastContainer>` is mounted once at
the app root.

## Step 9 — Edit

`DepartmentEdit.jsx` is the create form plus loading the current values. It uses the
REST-style URL `/departments/:id/edit`, which leaves `/departments/:id` for the read-only
details page (Step 13).

**Loading the values:** `useForm` accepts an **async `defaultValues`** function. Here it
calls `load()`, which fetches the department and fills the fields with `reset`:

```jsx
const { id } = useParams(); // from the URL: /admin/departments/:id/edit

const load = async () => {
    setLoading(true);
    try {
        const response = await showDepartment(id);

        reset({
            name: response.name,
            in_use: response.in_use,
            order: response.order,
            parent_id: response.parent_id,
            // slug is not sent: the backend regenerates it from the name.
        })
    } catch {
        // the interceptor already showed a toast
    } finally {
        setLoading(false);
    }
}

const { register, handleSubmit, formState: { errors }, reset, setError } = useForm({
    defaultValues: async () => load()
});
```

- `loading` covers fetching the department (spinner instead of the form).
- `disabled` covers submitting (Update button disabled).
- **`slug` is left out on purpose.** The backend's `prepareForValidation` generates the
  slug from the name when none is sent, so **renaming a department also changes its slug**.

**Saving:** `handleSubmit` passes the form values as `data`, and the call is
`updateDepartment(id, data)` (`PUT /admin/v1/departments/:id`). The success message says
`updated!` instead of `created!`.

## Step 10 — Delete

The delete logic is in the **parent** (`DepartmentsContent`), not in `DepartmentRows`.
The rows component only displays data and calls a function it receives as a prop:

```jsx
// DepartmentRows.jsx
<button type="button" onClick={() => onDelete(item)} className="btn btn-link text-danger fs-6 p-0 ms-2"><Trash /></button>
```

```jsx
// DepartmentsContent.jsx
const deleteDepartment = async (item) => {
  if (window.confirm(`Delete "${item.name}"?`)) {
    try {
      setLoading(true);
      await destroyDepartment(item.id);
      toast.success(`${item.name} deleted!`, { autoClose: 1000 });

      setDepartments(prev => prev.filter(d => d.id !== item.id));
    } catch {
      // the interceptor already showed a toast
    } finally {
      setLoading(false);
    }
  }
}
```

1. **Confirm first.** One misclick should not delete a department.
2. **A `<button>`, not a `<Link>`.** Deleting is an action, not navigation.
3. **The row is removed from state**, so the table updates without a second request.
4. **`prev` in `setDepartments(prev => ...)`:** when a setter receives a function, React
   calls it with the **current** state. After an `await`, the `departments` variable in
   the function may be out of date; `prev` never is.

## Step 11 — Show Server Validation Errors on the Field

Selecting a department as its own parent returns `422`:

```json
{
  "success": false,
  "message": "Validation failed",
  "code": 422,
  "errors": { "parent_id": ["A department cannot be its own parent."] }
}
```

The interceptor rejects with the axios error, so the details are in
`error.response.data.errors`, keyed by field name. `setError` from `react-hook-form` puts
each message on its field, the same way client-side rules like `required` do:

**`src/utils/form.js`**
```js
export const isInvalid = (errors, field) => {
    return errors[field] ? "is-invalid" : "";
};

// Laravel 422 errors ({ field: [messages] }) → react-hook-form field errors.
export const applyServerErrors = (error, setError) => {
    const fieldErrors = error.response?.data?.errors;
    if (fieldErrors) {
        Object.entries(fieldErrors).forEach((fe) => {
            const [fieldName, fieldMessages] = fe;
            setError(fieldName, { type: "server", message: fieldMessages[0] });
        });
    }
}
```

```jsx
} catch (error) {
    applyServerErrors(error, setError);
}
```

> **Very important:** Bootstrap only shows `.invalid-feedback` when the field before it
> has the `is-invalid` class. Without `isInvalid(errors, "parent_id")` on the `<select>`,
> `errors.parent_id.message` exists but is never visible.

```jsx
<select
    {...register("parent_id")}
    className={`form-select ${isInvalid(errors, "parent_id")}`} name="parent_id" id="parent_id">
    ...
</select>
{
    errors.parent_id && <span className="invalid-feedback">{errors.parent_id.message}</span>
}
```

- **Create uses it too.** A department can't be its own parent before it exists, but
  create still gets `422` for other rules, such as a duplicate name.
- Both helpers live in `src/utils/form.js`, not `constants.js`: they are functions, not
  fixed values. `isInvalid` takes `errors` as an argument because, outside the component,
  it can no longer read them from the closure.
- To see how `setError` fills the form state, log `errors` once from the component.

**Prevent it in the UI as well:** the edit form leaves the current department out of the
parent options:

```jsx
const data = state?.data?.filter(({id: itemId}) => itemId !== Number(id)) ?? [];
```

Keep the backend rule anyway: a department's child can't be its parent either, and only
the backend can check that.

## Step 12 — Parent Options Through Router State

The create and edit forms need all departments for the **Parent Department** select.
Instead of fetching them again, the list page passes the array it already has through
the link's `state`:

```jsx
// DepartmentsContent.jsx and DepartmentRows.jsx
<Link to="/admin/departments/create" state={{ data: departments }}>Create</Link>
<Link to={`/admin/departments/${item.id}/edit`} state={{ data }}>...</Link>
```

```jsx
// DepartmentCreate.jsx / DepartmentEdit.jsx
const { state } = useLocation();
const data = state?.data ?? [];
```

**When the state is there, and when it isn't:**

| How the page was opened | `state` |
|---|---|
| Edit / Create link from the list | present |
| Page refresh in the same tab | present: React Router keeps it in `history.state` |
| URL pasted, bookmarked, or opened in a new tab | `null`: the select has no options |

The data is also a snapshot from the moment the link was clicked. This is accepted for
now: a store will hold the departments later, and the forms will read from it.

## Step 13 — Show (Details) Page

`/admin/departments/:id` shows one department as a two-column table. The formatting
function is declared **outside** the component, because it uses no state or props:

```jsx
// Turns a department into [label, value] rows for the details table.
const prepareTableData = (data) =>
    Object.entries(data || {}).map(([key, value]) => {
        if (key === "in_use") return [key, value ? "yes" : "no"];
        if (key === "parent_id") return ["parent", value || "no parent"];
        return [key, value];
    });
```

The effect depends on `id`:

```jsx
useEffect(() => {
    // fetch showDepartment(id) ...
}, [id]);
```

**Why `[id]`:** going from `/departments/9` to `/departments/10` matches the same route,
so React Router **reuses the component** and only `id` changes. With `[]` the effect would
not run again and the page would keep showing department 9.

On failure, `department` stays `null` and the server's message is shown instead of the
table.

## Step 14 — Backend Notes: `DepartmentRequest`

Two Laravel details that the edit form depends on:

**1. `$this->route('department')` returns a model.**
With no argument, `$this->route()` returns the `Route` object. With a name, it returns
that **route parameter**. `Route::apiResource('departments', ...)` registers
`/departments/{department}`, and because the controller type-hints `Department $department`,
route model binding has already replaced the `9` in the URL with the model. On
`POST /departments` there is no `{department}`, so it returns `null`.

**2. `ignore($id)` keeps a department's own name valid on update.**

```php
$nameRule = Rule::unique('departments', 'name');

if ($department) {
    $nameRule = $nameRule->ignore($department->id);
}
```

`ignore(9)` adds `WHERE id != 9` to the uniqueness check. Without it, saving department 9
with its unchanged name (to change only `in_use`, for example) would fail with
"name has already been taken". The same `$department` feeds the
"cannot be its own parent" rule.

> **PUT vs PATCH:** `PUT` sends the whole resource (so `name` is required); `PATCH` sends
> only changed fields (so everything is `sometimes`). The client uses `PUT` because the
> form always sends every field. The `POST` and `PUT` rule blocks are identical and could
> be merged into one.

## Step 15 — Lint and Tests

The app runs with `docker compose up` (or `up -d`). With it running:

```sh
# Lint
docker compose exec frontend npm run lint

# Tests (run once)
docker compose exec frontend npm test

# Tests in watch mode (re-runs on file save, Ctrl+C to stop)
docker compose exec frontend npx vitest
```

If the container isn't running:

```sh
docker compose run --rm frontend npm run lint
docker compose run --rm frontend npm test
```

The tests use **Vitest**, not Jest. CI runs both, so a lint error fails the build.
