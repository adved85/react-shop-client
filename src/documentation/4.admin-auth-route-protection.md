# Admin Auth & Route Protection
### React Context + React Router — Step-by-Step Guide

---

## Overview

This guide documents how the admin area is protected: a shared `AdminContext` holds
the logged-in admin, a `RequireAdmin` wrapper guards private routes, and a generic
context helper gives clear runtime errors when a hook is used outside its provider.

**The chain used in this project:**

```
Login  →  AdminContext (state)  →  RequireAdmin (guard)  →  Protected route
```

---

## Step 0 — React Context in One Minute

Normally data flows **down** through props. If `App` holds the logged-in admin and
`Sidebar` — six levels down — needs it, you would have to thread it through every
component in between ("prop drilling"), and each of them takes a prop it does not care
about.

Context opens a side **channel** past all that:

```jsx
const ThingContext = createContext(null);   // 1. create the channel

<ThingContext.Provider value={something}>   // 2. publish a value on it
    <App />
</ThingContext.Provider>

const thing = useContext(ThingContext);     // 3. read it, at any depth
```

Four things to keep in mind:

| | |
|---|---|
| **Channel, not storage** | Context *transports* a value. The state itself still lives in a `useState` inside the provider component. |
| **Nearest provider wins** | A consumer reads the closest `Provider` above it **in the rendered tree** — not the nearest in the file. |
| **No provider = the default, silently** | With no `Provider` above it, `useContext` returns whatever you passed to `createContext(...)` — here `null`. It does **not** throw. That silence causes most context bugs, and Step 2 exists to break it. |
| **Changing `value` re-renders consumers** | That is what makes context usable as shared state. |

**Hook** — a function whose name starts with `use` that plugs into React's per-component
state machinery (`useState`, `useContext`, ...). The prefix is not a style rule: it is how
React and its lint plugins recognise a function as a hook so they can enforce that hooks
are only called at the top level of a component or of another hook — never inside a
condition, a loop, or a plain helper function. `useAdmin` and `useSafeContext` below are
custom hooks: ordinary functions that call other hooks, named `use*` so the machinery can
see them.

## Step 1 — The Problem

Two bugs made `RequireAdmin` fail silently / redirect forever:

1. `AdminContextProvider` was never mounted in `App.jsx`, so `useContext(AdminContext)`
   always resolved to the default value (`null`) and the helper below threw.
2. `Login.jsx` saved the admin to `localStorage` directly but never updated the
   context state, so `RequireAdmin` never found out the user had logged in.

Both are fixed below.

---

## Step 2 — Generic Context Helper

One helper is shared by every context hook (`useAdmin`, `useTheme`, ...). It throws
a **specific** error naming both the hook and the provider, instead of a generic message.

**`src/components/context/contextHelpers.js`**
```js
import { useContext } from "react";

export function useSafeContext(ctx, hookName, providerName) {
    const context = useContext(ctx);
    if (!context) {
        throw new Error(`${hookName} must be used within a ${providerName}`);
    }
    return context;
}
```

Each hook passes its own name + provider name:
```js
export function useAdmin() {
    return useSafeContext(AdminContext, "useAdmin", "AdminContextProvider");
}
```

> Without this, forgetting to mount a provider fails with a vague error (or a crash
> further down the component tree) instead of pointing straight at the missing provider.

## Step 3 — Admin Context + Provider

Holds the logged-in admin and exposes `login` / `logout`. Persists across reloads
via `localStorage`.

> **Changed since this layer was written.** These three exports originally lived in one
> `AdminContext.jsx`. The lint pass split them in two, because a file exporting both a
> component and a non-component breaks Fast Refresh
> (`react-refresh/only-export-components`). The code is otherwise unchanged, and
> `import { useAdmin } from "../context/AdminContext"` still resolves — the path is
> the same, only the extension changed.

**`src/components/context/AdminContext.js`** — the context and its hook
```js
import { createContext } from "react";
import { useSafeContext } from "./contextHelpers";

export const AdminContext = createContext(null);

export function useAdmin() {
    return useSafeContext(AdminContext, "useAdmin", "AdminContextProvider");
}
```

**`src/components/context/AdminContextProvider.jsx`** — the provider component
```jsx
import { useState } from "react";
import { AdminContext } from "./AdminContext";

export const AdminContextProvider = ({ children }) => {
    const adminStorage = localStorage.getItem("adminStorage");
    const [admin, setAdmin] = useState(adminStorage ? JSON.parse(adminStorage) : null);

    const login = (admin) => {
        setAdmin(admin);
    };
    const logout = () => {
        localStorage.removeItem("adminStorage");
        setAdmin(null);
    };

    return (
        <AdminContext.Provider value={{ admin, login, logout }}>
            {children}
        </AdminContext.Provider>
    );
};
```

**Why read `localStorage` in the initialiser.** React state dies on refresh; `localStorage`
survives it. Hydrating the initial state from storage is what keeps you logged in when you
hard-reload the dashboard — otherwise `admin` would start as `null` on every page load and
the guard would bounce you to login.

**Key point:** `localStorage.getItem` always returns a **string**, so it must be
`JSON.parse`d before going into state — otherwise `admin` is a truthy string forever
and `logout`/re-render checks behave oddly.

## Step 4 — Route Guard

Reads `admin` from context; redirects to login if there isn't one.

**`src/components/context/RequireAdmin.jsx`**
```js
import { Navigate } from "react-router-dom";
import { useAdmin } from "./AdminContext";

export const RequireAdmin = ({ children }) => {
    const { admin } = useAdmin();

    if (!admin) {
        return <Navigate to="/admin/login" />;
    }

    return children;
};
```

A component that renders its children **conditionally**. Not logged in → it renders a
`<Navigate>` instead, which React Router treats as a redirect. That is the entire
protection mechanism.

This only works if `AdminContextProvider` is an ancestor of wherever `RequireAdmin`
is rendered — see next step.

> ⚠️ **This is UI protection, not security.** The guard runs in the browser, where
> anyone can edit the JavaScript. It hides the admin screens; it does **not** protect
> data. The real protection is the API rejecting any request without a valid Sanctum
> token — see [guide 3](3.backend-api-integration.md). Never treat `RequireAdmin` as an
> authorisation boundary.

---

## Step 5 — Registering the Provider

`AdminContextProvider` wraps the router so **every** route (not just the protected
ones) can call `useAdmin()` if needed, and so `RequireAdmin` has a provider to read from.

**`src/App.jsx`**
```jsx
import { AdminContextProvider } from './components/context/AdminContextProvider';
import { RequireAdmin } from './components/context/RequireAdmin';

function App() {
  return (
    <AdminContextProvider>
      <BrowserRouter>
        <Routes>
          {/* ...public routes... */}

          <Route path="admin/login" element={<Login />} />

          <Route
            path="admin/dashboard"
            element={
              <RequireAdmin>
                <Dashboard />
              </RequireAdmin>
            }
          />
        </Routes>
      </BrowserRouter>
    </AdminContextProvider>
  );
}
```

> **The route shape changed later.** This flat `admin/dashboard` route is what this layer
> built. The next layer replaced it with a nested `/admin` parent route whose children
> render inside an `<Outlet>`, so the sidebar and page shell render once — see
> [guide 5](5.admin-dashboard-navigation-and-auth-hardening.md), Step 3, for the current
> shape. What matters here is unchanged: the guard wraps the protected element.

**Why `admin/login` sits outside the guard.** If the login route were wrapped in
`RequireAdmin` too, a logged-out visitor would be redirected to `/admin/login`, which
would itself be guarded, which would redirect again — an infinite loop. The page that
lets you *become* authenticated can never require authentication.

> Rule of thumb: a context provider must sit **above** every component (guard,
> page, or hook) that consumes it in the tree.

## Step 6 — Syncing Login With Context

`Login.jsx` must update **both** `localStorage` (for persistence across reloads)
**and** the context (for the current render tree to know immediately).

**`src/components/admin/Login.jsx`**
```jsx
import { useAdmin } from "../context/AdminContext";

const Login = () => {
    const navigate = useNavigate();
    const { login: setAdminSession } = useAdmin();

    const handleLogin = async (data) => {
        const resposeData = await login(data);
        const { token, user: { email, name, id, system_role } } = resposeData;

        const adminData = { token, email, name, id, system_role };

        localStorage.setItem("adminStorage", JSON.stringify(adminData));
        setAdminSession(adminData);   // <-- updates AdminContext state
        navigate("/admin/dashboard");
    };
    // ...
};
```

Without the `setAdminSession(adminData)` call, `admin` in context stays `null` even
after a successful login, and `RequireAdmin` bounces the user straight back.

**Both writes are needed, because they cover different timescales:**

| Write | Answers |
|-------|---------|
| `localStorage.setItem(...)` | "Am I still logged in **after a refresh**?" — survives the page, but React never watches it |
| `setAdminSession(...)` | "Am I logged in **right now**?" — re-renders every consumer immediately, but dies on refresh |

## Step 7 — Same Pattern for Other Contexts

`ThemeContext` reuses the exact same `useSafeContext` helper, so it gets the same
clear error message for free:

**`src/components/context/ThemeContext.js`**
```js
export function useTheme() {
    return useSafeContext(ThemeContext, "useTheme", "ThemeProvider");
}
```

Any future context (`CartContext`, `UserContext`, ...) should follow this pattern:
1. `XContext.js` — `createContext(null)` plus a `use*` hook calling
   `useSafeContext(Context, "useX", "XProvider")`
2. `XProvider.jsx` — the provider component owning the state
3. Mount the provider **above** every consumer in `App.jsx`

### Why the split — `react-refresh/only-export-components`

**Fast Refresh** is the Vite dev-server feature that swaps an edited component into the
running page *while keeping your application state*. Change a colour in the dashboard and
you keep your logged-in session; you do not get bounced back to the login screen.

It can only do that when it knows a file contains **nothing but components**. If a file
also exports a context object or a hook, React has no safe way to hot-swap it — those
values may be held by other modules — so it gives up and does a **full page reload**.
That reload wipes the very state you were testing.

Hence the rule, and hence the layout:

| File | Exports | Extension |
|------|---------|-----------|
| `XContext.js` | the context object + the `use*` hook | `.js` — no JSX, no components |
| `XProvider.jsx` | the provider component only | `.jsx` — components only |

A useful side effect: the extension now tells you what is inside before you open it.

## File Structure Summary

```
src/
├── App.jsx                              ← mounts AdminContextProvider, defines routes
└── components/
    ├── admin/
    │   ├── Login.jsx                    ← calls login() from useAdmin() on success
    │   └── Dashboard.jsx                ← protected page
    └── context/
        ├── contextHelpers.js            ← shared useSafeContext(ctx, hookName, providerName)
        ├── AdminContext.js              ← AdminContext + useAdmin
        ├── AdminContextProvider.jsx     ← AdminContextProvider (state, login, logout)
        ├── ThemeContext.js              ← ThemeContext + useTheme
        ├── ThemeProvider.jsx            ← ThemeProvider
        └── RequireAdmin.jsx             ← route guard, redirects to /admin/login
```
