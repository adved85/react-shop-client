# Backend API Integration
### React + Vite + Axios + React-Toastify — Step-by-Step Guide

---

## Overview

This guide documents how to wire a React (Vite) app to a backend REST API.  
It covers: environment config, axios client, interceptors, endpoint constants, a service layer, and toast error notifications.

**The 4-layer chain used in this project:**

```
Component  →  Service  →  API function  →  Axios client  →  Backend
```

---

## Step 1 — Install Packages

Enter the running container shell first:

```sh
docker exec -it vite_react_dev sh
# or
docker compose run --rm frontend sh
```

Install packages:

```sh
npm install axios
npm install react-toastify
```

If the packages are already in `package.json` but `node_modules` is missing (fresh container):

```sh
npm install
```

---

## Step 2 — Environment Files

Vite reads `.env` files automatically based on the current run mode.  
Create two files at the **project root** (next to `package.json`):

**`.env.development`**
```
VITE_API_URL="http://your-api.local/api"
```

**`.env.production`**
```
VITE_API_URL="https://your-api.com/api"
```

> **Rules**
> - Variables **must** be prefixed with `VITE_` — Vite strips anything else at build time.
> - `.env.development` loads when running `docker compose up` (dev mode).
> - `.env.production` loads when running `npm run build`.
> - Never commit secrets (tokens, passwords) to these files. Add them to `.gitignore`.

---

## Step 3 — Centralise Env Vars

Create a single config file that owns all `import.meta.env` access.  
If a variable name ever changes, you update it in one place.

**`src/config/env.js`**
```js
export const env = {
    apiUrl: import.meta.env.VITE_API_URL,
}

export const commonErrorCodes = [400, 401, 403, 404, 409, 422, 429];
export const retryErrorCodes  = [500, 503];
```

| Export | Purpose |
|--------|---------|
| `env.apiUrl` | The base URL passed to axios |
| `commonErrorCodes` | Client errors shown to the user via toast |
| `retryErrorCodes` | Server errors worth retrying automatically |

---

## Step 4 — Endpoint Constants

Never hardcode URL strings inside components or services.  
Keep all paths in one file and import from it everywhere.

**`src/api/endpoints.js`**
```js
export const ENDPOINTS = {
    auth: {
        login:   "/login",
        logout:  "/logout",
        refresh: "/refresh",
        me:      "/me"
    },
    adminAuth: {
        login:    "/admin/login",
        logout:   "/admin/logout",
        register: "/admin/register",
    }
}
```

Add a new object group for each resource: `products`, `orders`, `users`, etc.

## Step 5 — Axios Client with Interceptors

**`src/api/client.js`**

```js
import axios from "axios";
import { toast } from "react-toastify";
import { env, commonErrorCodes, retryErrorCodes } from "../config/env";

const MAX_RETRIES = 3;
const RETRY_DELAY = 1000; // ms

export const api = axios.create({
    baseURL: env.apiUrl,
    headers: { "Content-Type": "application/json" },
});
```

### Request Interceptor

Runs **before every request** is sent.

```js
api.interceptors.request.use(
    (config) => {
        const token = localStorage.getItem("token");
        if (token) {
            config.headers.Authorization = `Bearer ${token}`;
        }
        return config;
    },
    (error) => Promise.reject(error)
);
```

**What it does:**  
Reads the auth token from `localStorage` and attaches it as a `Bearer` header automatically — no need to set `Authorization` manually in every API call.

---

### Response Interceptor — Success Path

Runs after every successful response (`2xx` status).

```js
response => {
    if (response.data && response.data.data) {
        return response.data.data;  // unwrap nested { data: { data: ... } }
    }
    return response.data;
}
```

**What it does:**  
Normalises the response shape so callers always receive the payload directly, not the full Axios response object.

The API envelope this handles:
```json
{ "success": true, "message": "OK", "data": { ... } }
```

---

### Response Interceptor — Error Path

Runs after every failed response (non-`2xx`) or network error.

```js
async (error) => {
    const { response } = error;

    if (!response) {
        toast.error("Network Error: Please, check your internet connection.");
        return Promise.reject(error);
    }

    shouldRetrySpecificFailedRequests(error);

    if (commonErrorCodes.includes(response.status)) {
        toast.error(`Error ${response.status}: ${response.data.message}`);
    }

    return Promise.reject(error);
}
```

**What it does:**

| Condition | Action |
|-----------|--------|
| No response object | Network issue → show toast |
| Status in `retryErrorCodes` (500, 503) | Retry automatically |
| Status in `commonErrorCodes` (4xx) | Show server message via toast |
| All cases | Re-throw error so components can still react |

---

### Retry Helper

```js
async function shouldRetrySpecificFailedRequests(error) {
    const { response, config } = error;
    if (!config || config._retryCount >= MAX_RETRIES) return;
    config._retryCount = config._retryCount || 0;
    if (retryErrorCodes.includes(response.status)) {
        config._retryCount += 1;
        await new Promise(resolve => setTimeout(resolve, RETRY_DELAY));
        return api(config);
    }
}
```

Waits `RETRY_DELAY` ms then replays the original request. Stops after `MAX_RETRIES` attempts.

## Step 6 — API Functions (per resource)

Thin wrappers that call the axios instance with the right endpoint and payload.  
One file per resource group.

**`src/api/adminAuth.js`**
```js
import { api }       from "./client";
import { ENDPOINTS } from "./endpoints";

export const login    = (data) => api.post(ENDPOINTS.adminAuth.login,    data);
export const register = (data) => api.post(ENDPOINTS.adminAuth.register, data);
export const logout   = ()     => api.post(ENDPOINTS.adminAuth.logout);
```

Add more files as your app grows: `products.js`, `orders.js`, `users.js`, etc.

Optionally re-export everything from `src/api/index.js` as a barrel:
```js
export * as adminAuthApi from "./adminAuth";
export * as productsApi  from "./products";
```

## Step 7 — Service Layer

Services sit between components and raw API functions.  
They own business logic: storing tokens, transforming data, triggering side-effects.  
**Components call services — never API functions directly.**

**`src/services/authAdmin.service.js`**
```js
import * as adminAuthApi from "../api/adminAuth";

export async function login(credentials) {
    const response = await adminAuthApi.login(credentials);
    // e.g. localStorage.setItem("token", response.token);
    return response;
}

export async function logout() {
    const response = await adminAuthApi.logout();
    // e.g. localStorage.removeItem("token");
    return response;
}

export async function register(params) {
    const response = await adminAuthApi.register(params);
    return response;
}
```

> If you need to do anything with the response beyond returning it — store a token,
> transform data, log an event — do it here, not in the component.

## Step 8 — Toast Notifications Setup

`<ToastContainer>` must be rendered **once** at the app root.  
Register it in `src/main.jsx` — it then covers the entire app.

**`src/main.jsx`**
```jsx
import { StrictMode } from 'react'
import { createRoot } from 'react-dom/client'
import { ToastContainer } from 'react-toastify'
import App from './App.jsx'

import 'bootstrap/dist/css/bootstrap.min.css'
import 'react-toastify/dist/ReactToastify.css'   // required
import './assets/css/styles.scss'

createRoot(document.getElementById('root')).render(
    <StrictMode>
        <App />
        <ToastContainer position="top-right" autoClose={4000} />
    </StrictMode>,
)
```

Once registered, call `toast` from **any** `.js` or `.jsx` file — no component or hook required:

```js
import { toast } from "react-toastify";

toast("Plain message");
toast.success("Saved!");
toast.error("Something went wrong.");
toast.warn("Check your input.");
```

## Step 9 — Using It in a Component

```jsx
// src/components/admin/Login.jsx
import { login } from '../../services/authAdmin.service';

const handleLogin = async (data) => {
    try {
        const response = await login(data);
        // success: redirect, update state, store token
    } catch {
        // toast already shown by the interceptor
        // handle component UI state here (stop spinner, etc.)
    }
}
```

**Do I always need `try-catch`?**

| Goal | Needs try-catch? |
|------|-----------------|
| Show an error toast | **No** — the interceptor handles it |
| Stop a loading spinner on error | **Yes** |
| Redirect on success | **Yes** |
| Avoid Unhandled Promise Rejection in console | Add `.catch(() => {})` at minimum |
